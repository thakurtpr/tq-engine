# Addendum to prereg options-v1: ambiguities resolved before the first scored run

Dated 2026-11-06, written and committed BEFORE any development-window price, return, P&L, Sharpe or trade of any options-v1 variant was computed. It changes no threshold, window, variant, gate, seed-bearing axis or K of `docs/prereg-options-v1.md` (tag `prereg-options-v1`); it only fixes how the frozen text is implemented where it was ambiguous. If an item is later found wrong, the fix is a new dated addendum and the affected trials are counted again as new trials (a new OPEN ledger entry).

Pre-run checks were limited to unit tests on synthetic data, parsing and loading the downloaded files, the price-free structural report (`tq options-eval --structure-check`: cycle, skip-reason, fillability and lot-coverage counts; it computes no price, return or P&L), the implied lot-size derivation and the look-ahead harness. No variant was run on the real data before this commit.

## A. Data

1. **Files.** Fetched by `scripts/fetch_options_dev.py` from the NSE public archive for every session date of `data/index/NSEI.csv` from 2012-01-01 to 2021-12-31: old-format F&O bhavcopy (`fo<DD><MON><YYYY>bhav.csv.zip`) and `ind_close_all_<DDMMYYYY>.csv` (which also carries the India VIX row where NSE published it; no strategy uses VIX). Raw files live outside git in `/Users/thakur/Workspace/Trading/data-raw/options-v1`. The SHA-256 manifest of every zip, extracted CSV and index file plus `data/index/NSEI.csv` and the NIFTYBEES file is `docs/prereg-options-v1-data-manifest.sha256` (sha256 of the manifest itself `75893215eb6454cbcea73843cac2fce32f89a74da8b72d9a0790b6b693ed61c9`). Files NSE did not serve (404) are listed in the download log summary below; a missing option file removes that session, a missing index file removes that spot.
2. **Holdout guard.** The script and `tq-options` refuse any file dated on or after 2022-01-01 unless `--holdout-ack` is given; the loader checks the date in the NAME before opening a file; the NIFTYBEES reader stops at 2021-12-31. No holdout-dated file was downloaded or opened. Disclosure: while testing the script I once invoked it with `--holdout-ack` and a non-existent `--sessions` path (an ordering mistake in the command line); it failed on the missing file before any network or file access, so nothing was fetched. The flag was never used in any other call.
3. **Sessions** are the dates that have an option file. **Spot**: the `ind_close_all` closing value of `S&P CNX Nifty` / `CNX Nifty` / `Nifty 50` and `CNX Bank` / `Nifty Bank`; for NIFTY, where no index file exists (before 2012-03-01 and any gap) the `data/index/NSEI.csv` close is the fallback; BANKNIFTY has no fallback, so a cycle whose signal-day spot is missing is skipped and counted (reason: no index close). The date printed inside each index file must equal the date in its name.
4. **Format quirks handled and tested:** index files print `dd/mm/yyyy` on some dates; the 2012-05-14 option file prints two-digit expiry years; zero-volume rows carry a stale `CLOSE`. Malformed rows are errors, never skipped.
5. **Retention.** Per file and underlying, only the monthly expiries (the latest expiry of each calendar month listed in that file) and, within them, rows with volume > 0 or open interest >= 500 are kept. Weekly contracts, dead far strikes and other index symbols are not used.

## B. Cycles and calendar

6. A cycle is counted iff its entry day is >= 2012-01-01 and its next monthly expiry `D` is <= 2021-12-31; others are `excluded` (not counted, not skipped). Consequently the cycle signalled on the December-2021 expiry (entry 2021-12-31, expiry in January 2022) is excluded: its exit day lies in the holdout and its data must not be opened.
7. **Signal days are judged point-in-time.** A session `t` is a signal day for an underlying iff its own file lists, as the latest expiry of `t`'s calendar month, an expiry dated `t` (the monthly expiry day). This replaces a reading of "previous monthly expiry" as a calendar fact: a first draft that took each month's latest expiry over ALL files was flagged by the look-ahead harness (`tq bias lookahead --strategy options-v1`, LOOKAHEAD at the February 2014 expiry that NSE moved from the 26th to the 27th) and was replaced before any run. A weekly expiry day is not a signal day (its file's latest expiry of the month is the monthly). If a rescheduled expiry yields two signal days, the second, if it falls on or before the exit of the open position, is skipped and counted (`overlap`). `D` = the latest expiry of the calendar month after the signal day's month listed in the signal-day file (for three cycles, 2014-02 and 2018-03, NSE later moved that expiry by one day; the position then rides the originally listed contract and the carry and unfillable-exit rules of item 11 apply). Entry = next session (T+2 sensitivity: one session later); scheduled exit = last session strictly before `D`. A cycle whose entry is on or after that exit is skipped (counted).
8. Strikes: short strike = nearest listed strike with OI >= 500 on the signal day on the far side of `spot x (1 -/+ offset)`; the long strike = nearest such strike on the far side of `short strike -/+ w x spot` (w from the signal-day spot), always beyond the short strike. Straddle: the strike with OI >= 500 for both call and put nearest to spot, ties to the lower strike. Missing strikes skip the cycle.

## C. Fills, marks, exits

9. Entry fills need `CONTRACTS > 0` and `OPEN > 0` on the entry day for every leg (else skip, counted). Slippage `s = max(1% of open, Rs 1)` against us; a sell fill is floored at the Rs 0.05 tick.
10. Triggers are evaluated on the settle-quality marks at the close of every session from the entry day, and execute at the next session's open. A trigger that coincides with the scheduled exit day is a trigger exit (loss cut keeps its double slippage). Exits at a take profit and at the scheduled day use 1 x s; a loss cut uses 2 x s.
11. A leg with no settle-quality row (no volume that day) keeps its last valid mark (initially its entry fill); each carry is counted. An exit leg that is not fillable at the open (no volume or zero open) is closed at its last valid mark with 2 x s slippage and counted. Neither rule is a rescue of any gate.
12. Mark P&L: credit structures: `credit = sum(short fills) - sum(long fills)`, close cost = sum(short marks) - sum(long marks); captured = credit - close cost. Take profit when captured >= 50% x credit, loss cut when -captured >= 100% x credit. Straddle: value = call mark + put mark; take profit at value >= paid x (1 + tp), cut at value <= paid x (1 - cut). A credit <= 0 is a skip.
13. Straddle neighbour cells: `offset-20` = take profit 40%, `offset+20` = 60%, `width-20` = loss cut 40%, `width+20` = loss cut 60% (the registered order of the four non-base parameters).

## D. Sizing, margin, lots

14. Risk budget = 1.0% of current equity, equity = Rs 25,00,000 + closed-trade net P&L (before tax; tax is not fed back into sizing). Max loss per lot = (widest wing - credit) x lot, or premium paid x lot for the straddle, computed from the entry fills, plus modelled round trip costs = 2 x the costs of the entry orders for one lot. Lots = floor(budget / max loss per lot), at most 10; zero is a skip. Margin = max loss x lots, checked against 60% of equity.
15. **Lot sizes.** The prereg asks for a table from NSE circulars. NSE's circular archive could not be read in this session; web sources found are secondary (broker notes, a forum table) and incomplete before 2020. The table `docs/data/lot-sizes-nse.csv` (sha256 `ee748e818b18b0f2d639b3c5abb238474187c438f15039248921280fcd1e8784`) is therefore derived from the data itself: the implied lot of the most liquid index future of each file, `VAL_INLAKH x 10^5 / (CONTRACTS x price)`, rounded, changes accepted only when the new value persists for at least 10 sessions (`scripts/implied_lots.py`). **Every entry is marked `unverified`**; where a secondary source agrees it is named in the row. The prereg rule "a date range without a sourced lot size is excluded" is NOT applied (it would remove the whole window); instead the result reports the share of trades on unverified lot sizes (100%) and that a wrong lot size only scales the lot count and costs. This is a deviation from the prereg text, stated here before any run.

## E. Costs and tax

16. Costs as `docs/costs-tax-options-india.md` by date: Rs 20 per order (x2 stress), STT on sells 0.017% to 2016-05-31 and 0.05% from 2016-06-01 (dev), exchange 0.05% before 2024, SEBI Rs 10/crore, stamp 0.003% on buys for ALL years (conservative before 2020-07-01, when state duties applied), GST 18% on brokerage + exchange + SEBI. STT is not rounded per order; a trade's costs are summed unrounded.
17. Tax: 31.2% on positive financial-year (April to March) net P&L after costs and STT; losses netted inside the year, carried forward 8 years (a loss of year Y offsets years up to Y + 8), tax paid on the last session of the year present in the series (the unfinished final year on the last session of the window); sensitivities 20%, 39% and no carry-forward are re-computations of the same cells.
18. **Tax notes cross-check** (`docs/tax-india-fno.md`, secondary sources, unverified): STT on sold option premium 0.10% (from 2024-10-01) and 0.15% (from 2026-04-01) and exercise 0.125% -> 0.15% match the costs doc and the harness table. Mismatches flagged, none affects the dev window: (a) exchange charge on options 0.03503% (HDFC Securities, from 2024-10-01) vs 0.03553% (Zerodha page) vs the costs doc's 0.03553% from 2024-01-01 (the date is earlier than any source); (b) the tax audit threshold is Rs 1 crore (turnover) with Rs 10 crore at 95% digital in the tax notes vs Rs 2 crore / Rs 10 crore in the costs doc; (c) the notes call STT deductibility "unverified", the costs doc treats it as deductible; (d) the tax notes do not cover the 2013-2023 STT history used for dev (0.017% / 0.05%), which rests on the costs doc's secondary source; (e) the notes mark the Nifty lot size history and a claimed 2026 SEBI circular unverified, which is why lot sizes are data-derived here.

## F. Series and gates

19. **Scored series.** Daily after-tax account return = (day P&L - tax paid that day) / previous equity, flat days included, over every session of 2012-01-01..2021-12-31; **idle-cash interest is NOT part of the scored series** (a 6% credit on near-idle equity would give any variant that rarely trades a Sharpe and t far above the gates without any option edge). Interest at 6% on the share of start equity not held as margin is added only in the like-for-like account series used by O5 (rf = 6%), where it is subtracted again. This is a tightening relative to a literal reading. The 4% and 8% cash-rate sensitivities are not run.
20. O1: independent trades = closed trades; skip rate = skips / counted cycles; months = distinct entry months. O2: daily DSR from the ledger's `deflated_sharpe_for_sweep` (N = 30, recorded cross-trial variance floored at 1/T); monthly DSR with N = 30 and the variance of the 30 cells' monthly Sharpes (floored at 1/T); both must be >= 0.95; N = 6 and N = all ledger rows are informational. O3: PBO by CSCV over the six base-cell daily series, 16 blocks, on the last 16 x floor(T/16) sessions (the dropped leading sessions precede the first signal and are flat). O4: HAC t with the protocol-v3 automatic Newey-West lag; the gate value is the lowest of HAC and the monthly t when the monthly t is more than 0.5 below it (protocol 4c-x); Sharpe at rf = 0 on 252 days; CAGR of the compounded series. O5: strategy account series from the first trade entry vs NIFTYBEES buy-and-hold close-to-close over the same sessions (no benchmark costs or tax: favours the benchmark; price-based TRI proxy), Sharpe at rf = 6% and Calmar both greater. O6: "profitable" = positive compounded after-tax CAGR; at least 3 of 4 neighbours (70% of 4); median neighbour Sharpe (rf 0) >= 70% of the base Sharpe, which must be positive; 2x slippage and 2x brokerage: positive CAGR and gate t > 0; a fold (2015-H1 .. 2021-H2) is positive when its returns sum to > 0; net P&L without the 5 best trades > 0 (pre-tax trade nets). O7: worst trade = lowest pre-tax trade net (after slippage and costs) must be >= -1.5 x Rs 25,000; month-block bootstrap of the daily series, 10,000 draws, seed 20261108, p95 of the max drawdown <= 4% (0.8 x the 5% placeholder). O8: `tq bias lookahead --strategy options-v1` clean, a byte-identical repeat run of all 30 cells, and the guarded load.
21. **Operating run** (kill switch on): closed-trade equity falling 5% below its peak latches and blocks all later entries; reported as a sensitivity only. T+2 shift: entry one session later. Both are variants of the same cells, not trials.
22. **Overall rule** exactly as the prereg; an INCONCLUSIVE overall is the case "no GO-DEV and fewer than 4 KILL".

## G. Ledger and run protocol

23. The committed options-v1 sweep (OPEN, N = 30) is CLOSED with the 30 cell series by `close_open_sweep`; no sweep is opened. If that sweep is already closed when the study starts, a NEW sweep with the same manifest is opened first and its 30 trials count again (N rises).
24. Order of work for the scored run: data manifest and lot table committed, this addendum committed, then `tq options-eval --all` once. Nothing is re-run to improve a result; a re-run for a bug is a new trial and is reported.
25. Look-ahead check: the source `options-v1` in `tq-bias` tabulates, for every previous monthly expiry known on a view's last session, the next expiry and the condor and straddle strikes from the signal-day chain and spot, on views that cannot see later sessions; it also fails a source that reads the full store.
